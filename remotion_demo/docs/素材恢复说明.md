# 音频素材恢复说明

`public/` 中的配音和背景音乐为了避免版本库持续膨胀，没有直接纳入 Git。项目用 `manifests/audio-assets.json` 记录每个音频的名称、大小和内容指纹，确保换电脑或恢复时能确认拿到的是同一份素材。

## 日常检查

在移动项目、清理磁盘、交接电脑或正式出片前执行：

```powershell
npm run verify:audio-assets
```

通过表示当前 `public/` 中的音频和清单完全一致。若新加、替换或重新生成了配音，确认试听无误后执行：

```powershell
npm run manifest:audio-assets
```

这会更新清单；随后应与本期代码一起提交版本记录。

## 创建独立备份

备份必须放在项目文件夹之外，避免项目目录损坏时备份同时丢失。准备一个新的空文件夹后执行：

```powershell
npm run backup:audio-assets -- --dest E:\PPT动画流备份\2026-09-16
```

脚本会先核对当前音频，再复制音频和清单；若目标文件夹已有内容会拒绝覆盖。请把备份放在另一个磁盘、移动硬盘或经过授权的团队存储中。

## 发生误删时

不要直接覆盖恢复。先确认需要恢复哪些文件、是否存在人工备份，然后用备份中 `public/` 的对应音频补回项目的 `public/`，最后再次执行 `npm run verify:audio-assets`。自动化助手在发现误删时也必须先询问是否需要恢复，以及你是否保留了人工备份。
