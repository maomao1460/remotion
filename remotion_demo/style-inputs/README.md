# 风格输入文件

这里是每期视频的“填写页”。一份 JSON 文件对应一条短视频输入，不要放进 `episodes/`，以免与历史财经新闻的检查规则混在一起。

## 最简单的使用方法

1. 复制最接近的一份 `.demo.json`，改名为本期主题，例如 `2026-09-20-周末金融课堂.json`。
2. 填写标题、说明、三张信息卡和风险提示。
3. 填写 `review`：用户上传材料选 `user-provided` 并写明材料名称；外部核验内容选 `cross-checked` 并填写两个不同来源及链接；未审核内容保持 `draft`。
4. 如果画面中有会影响理解的核心数字，填写 `review.numericClaims`：每个数字写明各来源记录值、最终采用的来源，以及来源不一致时的处理理由。可复制 `templates/交叉核验模板.json` 中的写法。
5. 执行 `npm run validate:style-inputs`。有文字过长、风格误选、素材缺失、来源状态、核心数字核验或提示语缺失时，会直接指出位置。
6. 审核状态改为 `approved` 后，执行：

```powershell
npm run render:style -- --input style-inputs/活动推荐.demo.json --out out/活动推荐预览.mp4
```

程序不会默认覆盖已有视频。如果确实要替换同名预览文件，才在最后加 `--replace`。

出片完成后，程序会自动核对视频尺寸、帧率、时长和音轨，并在 `review/成片文件名/contact-sheet.jpg` 生成四格关键画面检查板。

如果想在出片前单独查看“来源—数字—采用口径”表，可执行：

```powershell
npm run review:style -- --input style-inputs/本期内容.json
```

它会在 `review/本期内容/content-review.md` 生成一份便于人工审核的记录。该记录是临时检查件；正式可追溯依据始终保存在本期 JSON 的 `review` 中。

## 风格选择

| 内容类型 | 默认风格 | 适用场景 |
| --- | --- | --- |
| `news` | `data-pulse` | 某一周期的核心新闻、关键数据和市场影响 |
| `product` | `product-trust` | 银行产品与服务介绍 |
| `activity` | `activity-calendar` | 银行活动、时间和参与方式 |
| `education` | `finance-education` | 投资者教育与金融知识讲解 |

默认匹配已经是推荐组合。若确实需要跨类型换风格，例如把一条政策科普改成“数据脉冲”，把 `styleId` 改为目标风格，并将 `allowManualStyleOverride` 设为 `true`。这样是有意切换，不会被误认为填错。

## 正式内容注意事项

- 产品内容：只能填写审核过的名称、费率、收益、风险等级和服务说明。
- 活动内容：日期、参与对象、规则、入口必须来自正式公告。
- 科普内容：必须保留风险提示，不能写成具体投资建议。
- 新闻内容：新数据须来自可核验来源；历史 `episodes/2026-09-13.json` 仍是迁移基线，不能视为已重新核实的事实。
- 用户上传内容：可跳过外部交叉验证，但必须写明 `userProvidedNote`；系统会保留“用户提供内容”状态，不能伪装成已交叉核验。
- 交叉核验：两个链接都能打开，不等于数字口径相同。凡是画面中的关键数值，都要在 `numericClaims` 写下“采用哪个来源、为什么采用”；系统会拦截来源编号错误、来源不足和误标“数值一致”的情况。
